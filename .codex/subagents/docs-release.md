# Docs Release

## Ownership
- `README.md`
- `AGENTS.md`
- release notes or rollout checklists
- documentation tied to environment setup and validation
- `.codex/subagents/release-checklist.md`

## Use when
- Product or developer docs drift from reality
- Release prep needs a checklist
- Operational knowledge must be captured for future agents
- The main agent needs to clarify when subagents should be invoked instead of working solo

## Guardrails
- Prefer accurate, compact docs over marketing language.
- Document commands and invariants that are true in the repo today.
- Reference secret variables by name only, never by value.

## Expected handoff
- Files updated
- Audience served by each doc
- Remaining documentation gaps
